# 4. The Android app is an Expo app on the shared core, and shows OpenCode Go only

Status: accepted

Date: 2026-10-15

## Context

The owner wants the usage meters on their Android phone too. Electrobun only builds for macOS,
Windows and Linux, so it cannot be the Android shell. The options were to keep Electrobun for Windows
and add a separate Android app, or to move both platforms to one shell (Tauri v2), Capacitor, or a
native Kotlin app. The owner prefers TypeScript on Bun, and the Windows app had just been confirmed
working.

Claude's usage endpoint needs an OAuth token. On the PC the tray reads the one Claude Code saved, but
a phone has no Claude Code. Since February 2026 Anthropic's terms say Free, Pro and Max sign-ins are
only for Claude Code and Claude.ai, and third parties may not offer Claude.ai logins.

## Decision

**`apps/android` is an Expo (React Native) app that imports `@ai-usage/core`, beside the unchanged
Electrobun app in `apps/windows`. It shows OpenCode Go only; Claude stays on the PC.**

- The core outside `packages/core/src/node` is platform-neutral and Biome enforces it (see
  `AGENTS.md`), so the phone runs the same parsers, Refresh and formatting as the tray.
- The OpenCode API key is typed into the app and kept with `expo-secure-store`. The app sets
  `allowBackup: false`, so the key never reaches another phone through Auto Backup.
- The version comes from the root `package.json`, and `versionCode` is
  `major × 1,000,000 + minor × 1,000 + patch`, so every Release Please bump can upgrade the phone.
- The native `android/` folder is generated by `expo prebuild` and not committed. CI builds a test
  APK on every PR and keeps it as a workflow artifact. It is the release variant signed with Expo's
  debug key: a debug APK leaves the JavaScript out and needs a running Metro server.
- Launcher icons are drawn from `iconLayout` by `bun run icons`, like the tray icon.
- The 1x1 home-screen widget uses `react-native-android-widget`, which renders JSX into Android's
  RemoteViews from a headless JS task. It draws the tray's two meters (`iconLayout`, as SVG via
  `iconSvg`) for OpenCode Go's 5-hour Window and its busiest longer Window, with the busiest percent
  above. Android wakes it every 30 minutes, its shortest `updatePeriodMillis`, and the app redraws
  it after every refresh. It keeps no history, so a failed background refresh shows a dash, not
  stale numbers. A separate background task (`expo-background-task`) would not refresh more often,
  since Android's floor for those is 15 minutes and is often stretched, so it is not used.

## Consequences

- No Claude on the phone. Adding it later means either a phone sign-in that breaks Anthropic's terms,
  or the PC relaying its numbers, which only update while the PC is on.
- The Windows app keeps the shell it was tested on, and both apps share every tested behaviour.
- Two shells to maintain, but each is thin, and the home-screen widget needs Android-specific code
  in any option.
- The widget lags the tray: up to 30 minutes old unless the app was opened since.
